# GLYPH ASCII Studio

把图片与本地短视频转换为字符画 / 字符短片，全部在浏览器本地完成，无需上传。

安装：`npm ci`

本地启动：`npm run dev`

测试：`npm test`（采样计划与时序滤波的纯函数测试，Node 22 直接运行）

Docker 启动：`docker compose up --build`，访问 http://localhost:18018。

## 视频 → 字符短片

在 01 / SOURCE 拖入视频（MP4 / WebM 等，500 MB 以内）后：

1. **选取时间范围**（04 / TIMELINE）：拖动时间轴上的起止手柄，或输入精确的
   起点 / 终点秒数（允许非整帧时刻），也可用「当前帧为起点 / 为终点」快速设定。
2. **采样帧率**：每秒提取的字符帧数（1–30）。采样按**时刻**取值，由解码器
   解析到该时刻实际对应的帧，因此可变帧率（VFR）素材同样正确；若终点没有
   落在采样网格上，会自动补上精确的终点帧，保证选区被完整覆盖。
3. **逐帧预览**：播放 / 暂停、上一帧 / 下一帧、拖动进度条逐帧定位。
   播放按墙钟推进，来不及显示的帧会被丢弃以保证流畅；
   拖动或逐帧步进时，未完成的旧解码任务立即失效，不会覆盖新画面。
4. **动态处理**：
   - *保留细节*：每帧独立映射，细节最多，但相邻帧可能闪烁；
   - *抑制闪烁*：对色调做因果时序滤波（当前帧与之前最多 2 个采样帧按
     二项式权重 [1,2,1] 混合），强度越高越稳定，代价是快速运动的边缘
     可能出现拖影（滞后不超过 2 个采样帧）。
   - 预览下方的 **Δ 相邻帧变化** 实时显示本帧与上一采样帧之间字符变化的
     单元数：静止画面下该值越小越不闪，运动画面下跟随越慢拖影越明显——
     可据此权衡强度。`npm test` 中的测试也量化验证了这对矛盾
     （抖动被压缩 vs 阶跃响应滞后）。
5. **离线导出**（结果区下方）：
   - *帧序列 .TXT*：全部帧的纯文本，帧之间以换页符 `\f` 分隔；
   - *HTML 短片*：自包含的播放器（内嵌全部帧数据与真实采样时刻），
     双击即可离线播放，支持播放 / 暂停 / 逐帧拖动，彩色设置随之一并导出。
   - 导出逐帧顺序渲染，显示进度条，可随时**取消**；
   - 导出使用开始时的设置快照，导出过程中修改设置或更换素材会立即中止，
     以保证产物与预览一致。

### 一致性保证

- 预览（含播放、逐帧拖动）与离线导出共用同一张采样时刻表、同一条
  `extractRaw → filteredTone → composeFrame` 渲染管线和同一种时序滤波
  窗口规则，因此**预览显示的字符帧与导出对应时刻逐帧一致**；
- 播放允许丢帧，但导出使用独立的视频元素按采样时刻表逐帧定位解码，
  **每一个选定采样时刻都会被包含**，实时播放时跳过的帧不会缺失；
- 每帧都沿用当前的裁剪区域与对比度 / 伽马 / 反转 / 字符集设置
  （与静态图片完全相同的代码路径）。
